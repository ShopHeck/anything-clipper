# Stock video pipeline via Pexels replacing still-image zoompan

The UGC pipeline now fetches real stock video clips from the Pexels Video API instead of applying a Ken Burns zoom effect to still images. The script structure expanded from 3 sections (hook/keyPoints/cta) to 5 sections (hook/problem/solution/demo/cta), and the 15-second hard cap on TTS was removed so scripts run at their natural 20-35 second duration. A new `pexels-video.ts` module handles API search, file selection, and download. The FFmpeg composition gained a dual-path filtergraph that handles video clip inputs (scale+crop+concat) alongside the legacy image+zoompan path.

**Watch for:** The UI page (`page.tsx`) was regressed to a 3-section display (hook/keyPoints/cta) while the backend now produces 5 sections — confirmed mismatch. Puppeteer was added as a production dependency which bloats the bundle with a Chromium download (~170MB). The Pexels API key absence silently falls back to the image pipeline with no logging or indication to the user that they're getting degraded output.

## High-level view

The script generation prompt and TTS chain now work on 5 natural sections with no duration ceiling. GPT produces both the voiceover text and Pexels search queries for each section in a single call, which is efficient but couples the search quality entirely to prompt engineering with no relevance validation.

The Pexels client is straightforward — search, pick best file (preferring mp4 at 1080p), download to disk. The pipeline degrades gracefully per-section: if Pexels returns no results, the scene planner falls back to images for that scene. However, the orchestrator uses a coarser gate: it falls back entirely to images if `PEXELS_API_KEY` is missing, but proceeds with a partial clip set if only some searches fail — producing a patchwork result with no user signal.

The FFmpeg composition branches per-scene: video clips get `scale+crop+setpts` while images keep the `zoompan` path. Both feed into the same `concat` filter. All clips are trimmed from the start with no offset control.

The `page.tsx` UI change is a regression: it collapses the script display from the existing 5 sections (which already appeared on main) down to the old 3-section format, directly contradicting the backend's new 5-section output.

## UI and backend script format divergence

The `page.tsx` diff removes `problem`, `solution`, `demo`, and `socialProof` from the script interface and replaces them with `keyPoints`. On `main`, the page already displayed 5 sections (hook/problem/solution/demo/socialProof/cta). The new backend produces a 5-section script (hook/problem/solution/demo/cta — dropping socialProof, adding nothing called keyPoints). So the UI now shows a field (`keyPoints`) that the backend never populates, and hides four fields the backend does populate.

The fix is to align `page.tsx`'s `UGCJob.script` interface and `SCRIPT_SECTIONS` to the new backend shape: hook, problem, solution, demo, cta.

## Puppeteer as a production web dependency

The `package.json` diff adds `"puppeteer": "^24.0.0"` to the `web` workspace's `dependencies` (not `devDependencies`). Puppeteer's post-install downloads a Chromium binary (~170MB). For a Next.js app deployed as a container or serverless function, this inflates image size and cold-start time substantially. It's used solely in `scrapeProduct` for JS-rendered pages (TikTok Shop). A lighter alternative: `puppeteer-core` with a pre-installed or shared Chromium, or a dedicated scraping microservice.

## Pexels client — file selection and silent landscape gap

`pickBestFile` filters for mp4, looks for exact 1080p (either orientation), then falls back to largest pixel count via `.sort()` — which mutates the caller's array. Use `[...candidates].sort(...)`.

The search hardcodes `orientation=portrait`, so landscape-only queries (common for product demos on flat surfaces) return zero results and the pipeline silently falls back to images for that section.

## Silent degradation and error handling in gatherAssets

The `gatherAssets` function catches all Pexels search errors per-section with a `console.warn` and continues. If 3 out of 5 searches fail (network blip, rate limit), the pipeline produces a 2-clip video with 3 image-fallback scenes — a patchwork result with no signal to the user. There's no structured error reporting or partial-failure status written to the DB row.

At the coarser level, if `PEXELS_API_KEY` is absent, the entire video-clip path is skipped. For a feature the user explicitly configured, this silent degradation could be confusing in production.

## FFmpeg clip offset limitation

Video clips are always trimmed from the start (`-ss 0 -t {dur}`). If the best moment in a 12-second stock clip is seconds 4-8, it won't be used. A future improvement could store a start offset per clip in the `VideoClipAsset` and pass it as the `-ss` value.

## Test coverage gaps

Not tested: the silent-fallback path in `gatherAssets` when only *some* searches fail (partial clip set behavior), the `page.tsx` UI rendering with the new script format, and the Puppeteer scraping integration (requires browser).
