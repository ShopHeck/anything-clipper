# End-to-end UGC pipeline fix: base64 upload, placeholder fallback, empty-URL guard (v2)

The pipeline now handles gpt-image-2's base64 response by decoding and uploading to R2, generates a placeholder PNG (raw bytes + zlib) when all image sources fail, and guards compose.ts against empty `imageUrl` scenes. The v1 review's two blocking concerns — placeholder upload crashing the pipeline and Date.now() key collisions — have both been addressed.

**Watch for:** The `strict: false` change to the chat completion schema weakens response validation for every JSON-schema caller (confirmed, but pre-existing from an earlier PR — out of scope for this task). The `sql.query()` → `sql()` migration change is similarly out of scope. Within the pipeline-specific changes, no blocking concerns remain.

**Verdict**: APPROVED

## High-level view

The image-gen module now detects `b64_json` in the OpenAI response, decodes it, uploads to R2 via presigned PUT, and returns a download URL. The upload helper returns `null` on failure, preserving the existing "URL or null" contract. Storage keys now include a `crypto.randomUUID()` suffix to eliminate collision risk.

The placeholder path in `gatherAssets` is wrapped in try/catch so a storage outage during fallback logs a warning and lets compose's own local-PNG fallback handle the gap. The pipeline degrades in two layers: first the orchestrator tries a remote placeholder, and if that fails, compose writes a local solid-color PNG for any scene with an empty `imageUrl`.

Two unrelated changes are bundled (`strict: false` in ai.ts and `sql()` in migrate.mjs). Both originate from a prior PR and are not part of the pipeline fix under review here.

## Prior concerns resolved

The placeholder call in `gatherAssets` is now wrapped in try/catch. On failure it logs a warning and returns empty assets, leaving compose to generate a local PNG per-scene:

```typescript
try {
  const placeholderUrl = await generatePlaceholderImage({ productName: product.name, userId });
  assets.productImages.push(placeholderUrl);
} catch (err) {
  console.warn('Placeholder image upload failed; compose will generate a local fallback:', ...);
}
```

## Two-layer fallback design

The pipeline's image resilience has three layers: (1) scraped product images, (2) AI-generated lifestyle image uploaded to R2, (3) placeholder PNG uploaded to R2 via the orchestrator. If all three fail, compose writes a local 1080×1920 solid-color PNG directly to its temp directory for any scene with an empty `imageUrl`. The only scenario that can still block video output is a local disk-full condition during composition — an infrastructure failure rather than an application-level gap.

## Test coverage gap

Not tested: the two-layer fallback in integration (orchestrator placeholder fails AND compose local-PNG fallback activates in sequence). Unit mocks cover each layer individually, which is acceptable for this change, but an integration test would catch any mismatch in the contract between the two fallback layers.
