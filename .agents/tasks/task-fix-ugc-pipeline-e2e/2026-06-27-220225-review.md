# End-to-end UGC pipeline: base64 upload, placeholder fallback, empty-URL guard

The pipeline now handles gpt-image-2's base64 response format by decoding and uploading to R2, generates a solid-color placeholder PNG (via raw bytes + zlib, no native deps) when all image sources fail, and guards compose.ts against empty `imageUrl` values in scenes. The approach keeps the pipeline from aborting on missing visual assets and ensures FFmpeg always receives valid image files.

**Watch for:** `Date.now()` storage keys create a (low-probability) collision risk under concurrent requests (confirmed). The `strict: false` change to the chat completion schema is unrelated to the UGC pipeline and weakens response validation for every caller (confirmed). `generatePlaceholderImage` throws on upload failure while `generateImage` returns null — the orchestrator doesn't catch it, which means a storage outage during placeholder upload crashes the pipeline instead of degrading gracefully (confirmed).

## High-level view

The image-gen module now inspects OpenAI's response for either a `url` or `b64_json` field. When base64 data arrives, it decodes, uploads to R2 via presigned PUT, and returns a download URL. The upload-or-null contract means the orchestrator doesn't need to know which model produced the image.

A new `placeholder-image.ts` constructs a valid PNG from raw IHDR/IDAT/IEND chunks with zlib compression. `createSolidPNG` is reused in `compose.ts` for scenes with empty URLs. Since `gatherAssets` now guarantees at least one image, the early-abort check is removed — but the guarantee depends on the placeholder upload succeeding, which can throw.

Two unrelated changes are bundled: `strict: true` → `strict: false` in the chat completion helper, and `sql.query()` → `sql()` in the migration script. Both alter behavior outside the UGC pipeline.

<summary>Issues (5)</summary>

1. **Placeholder upload failure crashes pipeline** — `generatePlaceholderImage` throws on upload failure, but `gatherAssets` doesn't wrap the call in try/catch. A storage outage during fallback would surface as an unhandled exception and mark the project failed with a generic message. Wrap in try/catch and push a local data-URL or skip gracefully.
2. **Date.now() key collisions** — Both `uploadBase64Image` and `generatePlaceholderImage` use `Date.now()` as the sole uniqueness component in storage keys. Two concurrent requests from the same user in the same millisecond would overwrite each other. Use a UUID or random suffix.
3. **strict: false weakens all JSON schema callers** — Changing `strict` from `true` to `false` in `chatCompletion` means the model is no longer contractually bound to respect `additionalProperties: false` or required fields. This affects every caller (scrapeProduct, generateUGCScript, scene planner), not just the pipeline fix. If this was intentional (schema incompatibility with strict mode), document it; otherwise revert.
4. **Unrelated migration script change** — `sql.query(statement)` → `sql(statement)` changes the DB driver call convention for migrations. If the tagged-template `sql` function behaves differently from `.query()` for raw DDL strings, migrations could silently break.
5. **1080x1920 placeholder is ~6 MB uncompressed scanline data** — `createSolidPNG` allocates `1 + 1080*3 = 3241` bytes per row times 1920 rows = ~6.2 MB raw buffer before zlib. The deflated output is small (solid color compresses well), but the transient allocation is notable for serverless functions with low memory limits. Not blocking, but worth profiling.

## Base64 decode and upload: Date.now() collision risk

The storage key `generated-images/${userPrefix}/${Date.now()}.png` uses millisecond timestamps as the sole uniqueness factor. Under concurrent generation for the same user, two requests resolving in the same millisecond overwrite each other silently. The same pattern appears in `generatePlaceholderImage`. A UUID suffix eliminates this:

```typescript
const storageKey = `generated-images/${userPrefix}/${Date.now()}-${crypto.randomUUID().slice(0, 8)}.png`;
```

The upload uses `new Uint8Array(buffer)` as the fetch body, which copies the buffer. For gpt-image-2 PNGs (4-8 MB), passing the Buffer directly would halve peak memory.

## Placeholder image: error contract asymmetry

`generatePlaceholderImage` **throws** when the upload fails, while `generateImage` **returns null** on any failure. In `gatherAssets`, the placeholder call is unwrapped:

```typescript
if (assets.productImages.length === 0 && assets.lifestyleImages.length === 0) {
  const placeholderUrl = await generatePlaceholderImage({ productName: product.name, userId });
  assets.productImages.push(placeholderUrl);
}
```

If R2 is down during the fallback path, this throws and bubbles to the top-level catch. The whole point of the placeholder was to prevent pipeline failure. Either wrap in try/catch and fall through (letting compose's own solid-PNG fallback handle it), or change `generatePlaceholderImage` to return `null` like `generateImage`.

## strict: false in chatCompletion (unrelated)

With `strict: true`, the model is obligated to produce output matching the schema exactly — no extra keys, all required fields present. With `strict: false`, the model can hallucinate extra fields or omit required ones. The `scrapeProduct` and `generateUGCScript` schemas use `additionalProperties: false` and `required` arrays that rely on strict enforcement.

If this was changed because certain schema shapes are incompatible with strict mode (e.g., optional fields), document it in a comment. Otherwise it degrades reliability for every downstream consumer.

## migrate.mjs: sql.query → sql tagged template (unrelated)

The migration script changed from `sql.query(statement)` to `sql(statement)`. If `sql` is Postgres.js, calling it as a function (not as a tagged template) with a raw DDL string may not behave identically to `.query()`. Worth verifying against the actual driver.

## Test coverage gaps

Not tested: concurrent `Date.now()` collision behavior, `createSolidPNG` with 0 or negative dimensions, and whether the `strict: false` change causes any downstream schema parsing to accept malformed responses.
